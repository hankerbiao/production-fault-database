# Sales Status Simplification Implementation Plan

**Goal:** 修正历史状态刷新的范围、明细匹配和内存问题，移除闲置前端状态分支。

**Architecture:** 复用临时 SQLite Snapshot，增加按业务组索引和按键读取。SAP 完整返回的 `(source, AUFNR)` 集合定义本次核对范围；每个本地订单先完整检查代表行和明细，再产生一条更新操作。保留集合锁和批量写入。

**Tech Stack:** Python、SQLite、PyMongo、pytest、React、Vitest、Playwright。

## 约束与范围

- 用户已授权设计并开始优化；直接在当前仓库实施。
- P1 部署密码配置保持现状，本次不修改部署脚本。
- 不连接生产 SAP 或 MongoDB，不执行维护或同步命令。
- 不新增依赖、数据库集合、持久化索引、兼容分支或自动修复。
- 不把 `GSTRS` 当作 `CHDAT`：当前接口契约没有给出两者等价的依据。

## 设计

### 核对范围

完整读取并校验两来源的响应后，以源实际返回的订单身份定义本次范围。遍历本地订单时：

- 出现在快照中的订单：验证代表行及所有已有明细。
- 未出现在快照中的订单：计入 `not_returned`，保留有限样本，不更新、不声明已核对，也不据此判定失败。
- 快照中的新订单：状态刷新不负责导入。

摘要明确包含 `scope: returned_orders`。空的合法响应代表本次没有可核对订单；请求异常、响应结构异常和同键不同状态仍在任何目标写入前失败。

当前接口无法区分“源漏单”和“本地订单不在 CHDAT/产品层次窗口内”。因此 `not_returned` 只表示未覆盖，不能据此宣称历史全量状态已经核对完毕。若未来需要严格检查源收缩，必须先建立可验证的本地日期范围或源完整性契约，不能通过猜测计划日期补齐。

### 严格匹配

代表行及明细统一使用 `source + MANDT/AUFNR/VBELN/POSNR/ETENR/MATNR` 查询快照，不再使用单行兜底。

同一订单只要有任一代表行或明细未匹配、状态缺失或为 null，就不生成该订单的更新操作，也不写核对元数据。该阶段报告失败，不推进销售订单水位；其他完整匹配订单可保持现有非事务批量提交行为。

空字符串是明确的源状态，继续允许写入。`would_update` 和状态迁移统计仅包含通过完整验证的订单，预览与正式写入使用相同计划。

### 有界内存

Snapshot 增加可选分组键、分组存在查询及主键读取。未使用分组的现有调用保持行为不变，分组采用临时 SQLite 的部分索引。

状态快照仅保存按唯一行键索引的状态值，并按订单身份分组；读取本地游标时直接查询 SQLite。删除全量 `orders` 字典，每次只保留当前订单和一个写入批次。源 HTTP 接口仍每个日期窗口一次性返回列表，此次不改变该接口契约。

### 前端精简

删除没有配置使用的 `autoLoad` 参数和 `hasLoaded` 状态，保留现有首次加载、分页与刷新行为。
